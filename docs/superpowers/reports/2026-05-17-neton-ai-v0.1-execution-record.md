## 2. Capabilities by feature

- ✅ **Provider abstraction (single-layer SPI)**: `AiProvider` / `AiTextModel` / `AiStreamingTextModel` / `AiEmbeddingModel` / `ProviderCallRequest` / `ProviderCallResponse` / `ProviderRegistry`.
- ✅ **OpenAI-compatible adapter** (`OpenAiCompatibleProvider`): covers OpenAI, DeepSeek, Qwen (DashScope compat mode), OpenRouter compat. Includes `/chat/completions` (non-stream + SSE stream) and `/embeddings`.
- ✅ **Anthropic adapter** (`AnthropicProvider`): native `/v1/messages` with event-typed SSE (`message_start` / `content_block_*` / `message_delta` / `message_stop` / `ping` / `error`). System message merge, tool_use blocks, tool_result-as-user, cumulative `message_delta.usage` semantics.
- ✅ **Chat (non-streaming) `generateText`**: provider-neutral request/result, multi-round local tool loop, model routing with fallback, usage recording per round.
- ✅ **Chat streaming `streamText`**: full SSE per provider, `Flow<AiStreamEvent>` with `Started` emitted by `AiClient` after first provider event, fallback only before first event, multi-round tool loop streaming.
- ✅ **Tool calling**: `AiToolDefinition` + `AiToolExecutor` fun-interface; typed-tool DSL via `kotlinx.serialization` (caller still supplies `inputSchemaJson` — auto-generation deferred to v0.2); local-executor lifecycle owned by `AiClient`; spec §3.7 algorithm with all branches covered.
- ✅ **Embeddings**: `AiClient.embed { ... }`, OpenAi-compat implementation (Anthropic intentionally returns null for `embeddingModel()` since the API does not exist).
- ✅ **Routing**: explicit (no fallback) > policy (prefer+fallback list, fallback only on fallback-eligible `AiError`) > default (no fallback). `AiError.isFallbackEligible()` defines transient eligibility (Network/Timeout/RateLimited/ServerError 5xx).
- ✅ **Usage recording**: `AiUsageRecorder` SPI + `NoopAiUsageRecorder` + `LoggingAiUsageRecorder` (allowlist metadata filter); `UsageAggregator` for cross-round sums with null-safe handling.
- ✅ **TOML config** (`config/ai.conf`): camelCase per Neton convention; `AiConfig.applyFileMap` merges file → DSL explicit override → built-in defaults; per-provider field-level merge for same id.
- ✅ **Dual usage**:
  - **Mode 1** (any KMP/Native project): `AiClient.create { httpClient = ...; providers { ... }; routing { ... } }`. Zero `neton.core` / `neton.logging` imports in standalone path (verified by `AiClientFactoryStandaloneTest` contract guardrail).
  - **Mode 2** (Neton Framework): `Neton.run { httpClient { }; ai { ... } }`. `AiComponent` is a thin adapter; loads `ai.conf`, binds `AiClient` to `NetonContext`.
- ✅ **Redaction**: provider TextModels apply `withRedactedValues()` to headers before emitting any debug log line. Verified by `RedactionVerificationTest` (planted `sk-SECRET-DO-NOT-LEAK` API key never appears in captured logs).
- ✅ **Cancellation propagation**: `Flow.cancel` → `NetonHttpClient.stream` channel closes → Ktor body closes → TCP closes → no synthetic `AiStreamEvent.Failed`.

## 7. Deferred to v0.2 (and beyond)

Strictly out of v0.1 scope; do **not** start without a fresh spec/plan iteration.

- **Gemini provider** (native `generateContent` + non-standard streaming) — spec §3.1 explicit defer
- **Multimodal `AiContent`**: `ImageUrl` / `ImageData` / audio variants — spec §3.2 sealed interface allows non-breaking extension
- **Automatic JSON Schema generation** from `@Serializable` types — spec §9 open item
- **Anthropic prompt cache** token reporting (`cache_read_input_tokens` / `cache_creation_input_tokens`) — spec §9
- **OpenAI Responses API** (`/v1/responses`, o-series reasoning models) — separate adapter
- **`streamObject` / structured output** beyond basic JSON mode — spec §9
- **Dedicated metrics SPI** (OpenTelemetry / Micrometer) — currently consumers must subscribe via `AiUsageRecorder`
- **`HttpClientComponent` config DRY refactor** (manual field copy from `HttpClientConfig` into `NetonHttpClient.create { ... }` block) — flagged in PR0 final review
- **Migration of `neton-storage` and `privchat-client`** to use `neton-http-client` — explicitly out of scope; their direct Ktor usage is preserved

## 8. Known follow-ups (not blockers)

1. **`HttpClientComponent` field-copy DRY risk** (PR0 final review). If `HttpClientConfig` adds fields in v0.2, `HttpClientComponent.init` must be updated in sync. Suggested fix: `NetonHttpClient.create(config: HttpClientConfig)` overload that accepts the config object directly.

2. **`HttpClientConfig.debug` is also a `HttpClientConfig` field** but never read by `DefaultNetonHttpClient` (no HTTP-level logging in PR0). Currently only `HttpClientComponent` reads it to gate its own init-time log. Document or remove in v0.2.

3. **`NoRetryPolicy` is the only `NetonRetryPolicy` ship in PR0.** No `ExponentialBackoffWithJitter` etc. — `neton-ai` does not currently use HTTP-level retry; router fallback covers most cases. Reconsider when adding rate-limited backoff in v0.2.

4. **`AiUsageRecorder` is never invoked in the streaming path** in v0.1. Non-streaming `ToolLoop` records per round; `StreamingToolLoop` does not. Add usage recording calls in v0.2 streaming when the API stabilizes.

5. **`Logging recorder` value sanitation is allowlist-based on keys only**, not value content. Callers MUST NOT put PII / prompt text / secrets into `request.metadata`. Currently documented in `AiUsageEvent` KDoc; could be hardened with value-shape validation in v0.2.
